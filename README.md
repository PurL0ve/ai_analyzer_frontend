# AI Skill Analyzer 前端

基于React和Vite的技能匹配页面，配合FastAPI后端使用。支持手动技能匹配，也支持粘贴JD后由后端调用模型提取岗位要求，再用规则计算匹配结果。

## 当前功能

- 手动分析：输入岗位名称、本人技能和岗位要求，点击“开始分析”，展示匹配/缺失技能与匹配率；后端保存该分析记录。
- JD分析：输入本人技能和岗位描述，点击“从JD分析”；调用 `POST /analyze-jd`，不需要填写岗位名称或手动岗位要求。目前这条流程不保存历史。
- 技能输入使用英文逗号分隔；请求前去除首尾空格并过滤空项。
- 修改输入时隐藏旧结果；两个分析按钮共用加载状态，请求期间禁用输入和分析按钮，结束后恢复。
- 空输入有前端提示；请求失败时隐藏结果并显示错误。
- 手动加载历史，显示岗位、匹配率和从1开始的展示编号，支持收起/展开。展示编号不是数据库真实ID，React列表的 `key` 仍使用真实ID。
- 历史请求有独立加载/失败状态，空列表有提示。

## 环境与依赖

本机检查到的工具版本：Node.js `22.19.0`、npm `10.9.3`。项目依赖声明在 `package.json`，具体安装版本由 `package-lock.json` 记录。

在 Windows PowerShell 中进入前端目录，其他存放位置请替换路径：

```powershell
cd D:\ai_analyzer_frontend
node --version
npm --version
```

首次准备新环境，或需要按锁文件重新安装依赖时执行：

```powershell
npm ci
```

`npm ci` 按锁文件安装依赖，并会替换已有的 `node_modules`。现有依赖可用时，日常启动无需重复安装。本项目尚未完成全新环境安装验证。

## 启动与前后端连接

1. 先按后端项目的 README 准备 MySQL、数据库连接和 Python 环境，再启动后端。当前本机后端目录为 `D:\ai_analyzer`。
2. 另开一个终端，在前端目录执行：

```powershell
npm run dev -- --port 5173 --strictPort
```

3. 浏览器打开 `http://localhost:5173`，保持前后端两个终端运行。需要停止对应服务时，在该终端按 `Ctrl+C`。

固定5173端口并在占用时停止启动，是为了与当前后端跨域配置一致。若提示端口占用，先确认是否已有本项目运行，不能直接停止未知进程或换端口后忽略跨域设置。

当前前端源码使用以下后端地址：

- `POST http://127.0.0.1:8000/analyze`：分析并保存。
- `POST http://127.0.0.1:8000/analyze-jd`：JD提取与匹配，暂不保存。
- `GET http://127.0.0.1:8000/history`：查询手动分析历史。

当前后端允许的前端来源为 `http://localhost:5173`。前端页面请使用这个地址；`http://127.0.0.1:5173` 属于不同来源。后端地址仍可使用源码中的 `127.0.0.1:8000`。

## 最小运行检查

1. 填写岗位名称，本人技能输入 `python`，岗位要求输入 `python,sql`。技能之间使用英文逗号。
2. 点击“开始分析”，预期匹配技能为 `python`、缺失技能为 `sql`、匹配率为 `50.0%`。
3. 点击“加载历史”，核对刚保存的岗位、匹配率和编号。新记录暂不自动刷新到列表，需要手动加载。
4. 首次进入尚未加载时，不显示已加载条数；查询失败时应显示错误并恢复按钮。已有列表可能保留此前成功加载的数据，不代表最近一次请求成功。

### JD分析的使用步骤

1. 后端本机配置有效 `DEEPSEEK_API_KEY`，按后端README准备环境和数据库；密钥只放后端，前端不填写。
2. “我的技能”填写英文逗号分隔的技能，在“岗位描述”粘贴JD；岗位名称和手动岗位要求可以留空。
3. 点击一次“从JD分析”，等待结果。非空有效输入会真实调用外部模型并使用API额度，不要连续点击。
4. 核对模型相关结果。页面匹配率表示规则下的技能匹配程度，不是录用概率。

检查输入提示不需要真实模型请求；页面请求失败测试应与正常分析分开。已有成功截图时，不为重复证明旧结果再次请求。后端SDK未显式关闭默认重试，单次点击不保证只有一次底层网络尝试。

## 已有验证与限制

2026-10-22有指导实现、本人实际操作的证据包括：

- 前端空输入点击“从JD分析”，提示“请填写我的技能和岗位描述”，在发送请求前停止。
- 本人技能 `Python,MySQL`、JD明确要求Python/FastAPI/MySQL时，实际显示匹配python/mysql、缺失fastapi、66.7%；网络面板 `analyze-jd` 请求实际HTTP200。
- 请求等待时两个按钮显示分析中，成功后恢复；本地后端不可用场景下，有效输入请求失败显示“JD分析请求失败，请稍后重试”，页面无结果卡，按钮恢复空闲外观。
- JD输入框宽度、高度、标签和按钮文案有本人截图；`textarea` 常态样式和 `:focus` 聚焦边框已分开。
- 本人 `npm run build` 实际通过：Vite 8.3.1、18 modules transformed。构建不是公开部署或所有页面行为验收。

旧手动分析与历史流程有此前的运行记录，但这轮没有把所有旧场景重新跑一遍。历史空列表提示曾用前端临时空数组练习，不能当作后端真实空库联调。网络面板中的 `preflight` 是跨域预检，不是第二次模型分析。

目前限制：

- JD分析结果不加入历史；点击“加载历史”不会出现本次JD分析的新记录。
- 实际SDK超时、后端502等未逐一完成页面验证，现有JD错误提示仍是统一提示。
- 尚未完成全新环境安装与公开部署验证，也未实现多用户认证/数据隔离、RAG或Agent。
- 本项目为AI辅助和分步指导下的学习实践，不代表全部功能无提示独立完成。
