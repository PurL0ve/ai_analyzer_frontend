# AI Skill Analyzer 前端

基于React和Vite的技能匹配页面，配合FastAPI后端使用。支持手动技能匹配，也支持粘贴JD后由后端调用模型提取岗位要求，再用规则计算匹配结果。

## 当前功能

- 手动分析：输入岗位名称、本人技能和岗位要求，点击“开始分析”，展示匹配/缺失技能与匹配率；后端保存该分析记录。
- JD分析：填写岗位名称、本人技能和岗位描述，点击“从JD分析”；调用 `POST /analyze-jd`，不需要手填岗位要求。后端在匹配成功并提交数据库后返回，记录可通过“加载历史”查看。
- 技能输入使用英文逗号分隔；请求前去除首尾空格并过滤空项。
- 修改输入时隐藏旧结果；两个分析按钮共用加载状态，请求期间禁用输入和分析按钮，结束后恢复。
- JD的岗位名称、本人技能和岗位描述有前端空输入校验；请求失败时不展示结果。HTTP失败回复中detail为非空字符串时显示具体文字，否则使用“JD分析请求失败，请稍后重试”；网络失败或正文解析失败也使用通用提示。
- 手动加载已保存的手动/JD分析历史，显示岗位、匹配率和从1开始的展示编号，支持收起/展开。展示编号不是数据库真实ID，React列表的 `key` 仍使用真实ID；来源字段manual显示“手动输入分析”、jd显示“JD提取分析”，其他值（含旧记录null）显示“历史未标记”；新记录不会自动刷新。
- 历史请求有独立加载/失败状态，空列表有提示。

## 环境与依赖

本机检查到的工具版本：Node.js `22.19.0`、npm `10.9.3`。项目依赖声明在 `package.json`，具体安装版本由 `package-lock.json` 记录。

在 Windows PowerShell 中进入前端目录，其他存放位置请替换路径：

```powershell
cd D:\ai_analyzer_frontend
node --version
npm --version
```

首次准备新环境，或需要按锁文件重新安装依赖时执行：

```powershell
npm ci
```

`npm ci` 按锁文件安装依赖，并会替换已有的 `node_modules`。现有依赖可用时，日常启动无需重复安装。本项目尚未完成全新环境安装验证。

## 启动与前后端连接

1. 先按后端项目的 README 准备 MySQL、数据库连接和 Python 环境，再启动后端。当前本机后端目录为 `D:\ai_analyzer`。
2. 另开一个终端，在前端目录执行：

```powershell
npm run dev -- --port 5173 --strictPort
```

3. 浏览器打开 `http://localhost:5173`，保持前后端两个终端运行。需要停止对应服务时，在该终端按 `Ctrl+C`。

固定5173端口并在占用时停止启动，是为了与当前后端跨域配置一致。若提示端口占用，先确认是否已有本项目运行，不能直接停止未知进程或换端口后忽略跨域设置。

当前前端源码使用以下后端地址：

- `POST http://127.0.0.1:8000/analyze`：分析并保存。
- `POST http://127.0.0.1:8000/analyze-jd`：传入position、user_skills和jd，进行JD提取、匹配并保存记录。
- `GET http://127.0.0.1:8000/history`：查询已保存的手动/JD分析记录。

当前后端允许的前端来源为 `http://localhost:5173`。前端页面请使用这个地址；`http://127.0.0.1:5173` 属于不同来源。后端地址仍可使用源码中的 `127.0.0.1:8000`。

## 最小运行检查

1. 填写岗位名称，本人技能输入 `python`，岗位要求输入 `python,sql`。技能之间使用英文逗号。
2. 点击“开始分析”，预期匹配技能为 `python`、缺失技能为 `sql`、匹配率为 `50.0%`。
3. 点击“加载历史”，核对刚保存的岗位、匹配率、编号及“来源：手动输入分析”。新记录暂不自动刷新到列表，需要手动加载。
4. 首次进入尚未加载时，不显示已加载条数；查询失败时应显示错误并恢复按钮。已有列表可能保留此前成功加载的数据，不代表最近一次请求成功。

### JD分析的使用步骤

1. 后端本机配置有效 `DEEPSEEK_API_KEY`，按后端README准备环境和数据库；密钥只放后端，前端不填写。
2. 填写岗位名称；“我的技能”填写英文逗号分隔的技能，在“岗位描述”粘贴JD。只有手动“岗位要求”可以留空。
3. 点击一次“从JD分析”，等待结果。通过校验后会请求外部模型，成功匹配会保存一条历史记录；不要连续点击或重复写入同一验证样例。保存失败时后端返回500，不作为保存成功展示。
4. 核对提取与匹配结果，再点击“加载历史”查看已保存的岗位、匹配率及“来源：JD提取分析”。页面匹配率表示名称规则下的技能匹配程度，不是岗位胜任度或录用概率。

检查输入提示不需要真实模型请求；页面请求失败测试应与正常分析分开。已有成功截图时，不为重复证明旧结果再次请求。后端业务提取客户端现设置 `timeout=30`、`max_retries=0`，网络操作等待超时为30秒，失败后不自动重试；它不是整个接口严格30秒的总耗时上限。参数修改仅做静态核对，尚未据此重跑正常外部模型请求。

- 旧版真实JD页面显示匹配python/mysql、缺失fastapi、66.7%，网络面板中JD请求HTTP200；当时尚无本次岗位名称必填和保存逻辑。

2026-10-24新增证据：

- 晚间使用占位密钥和本机端点补充超时验证：模拟APITimeoutError可被业务函数捕获；另一次真实SDK本地请求输出APITimeoutError/ConnectTimeout；再将实际本地SDK客户端交给原提取函数，得到超时提示及None。最后一轮未打印底层异常类型，也未经过网页/HTTP接口，不推定网页超时或502联合链路通过。未调用DeepSeek，资源按本人反馈已关闭。

- 当前版本真实网页样例 `JD真实闭环验证_20261024_01` 显示匹配python/mysql、缺失fastapi、66.7%；网络响应正文code200/message success；加载历史显示同名岗位及66.7%。支持该样例真实提取、匹配、保存及历史展示通过；截图未展示Headers页HTTP状态，不由正文code推定实测HTTP状态。
- 旧记录的history响应包含source:null，页面显示“历史未标记”；新手动样例返回source:manual、rate:0.5，网页对应显示来源；JD来源样例临时固定提取Python/FastAPI，请求HTTP200、rate:0.5，历史显示JD来源，随后恢复替换。该来源测试没有调用真实模型。
- 最终显示文字局部调整后，本人加载历史，截图确认“手动输入分析”“JD提取分析”和“历史未标记”三类显示；这次仅查询历史，没有新增分析记录或模型请求。

- 有效技能和JD、岗位名称留空时，页面显示“请填写岗位名称”，对应代码在fetch前返回；后端TestClient输入空格岗位名返回400及“岗位名称不能为空”。
- 浏览器临时替换fetch模拟HTTP502，文字detail显示“JD技能提取失败”，空对象正文显示“JD分析请求失败，请稍后重试”；截图支持错误文字、未见结果卡与按钮空闲外观，不单独证明所有点击/输入行为恢复。

- Mock替代数据库会话并模拟提交失败，JD接口返回500及“数据库保存失败”，回滚方法被调用1次；不是实际数据库故障后的事务状态验证。

目前限制：

- 历史记录共用现有表，已保存manual/jd来源；旧记录来源保持null并显示“历史未标记”，未保存JD全文。需要手动加载，没有分页或明确排序。展示编号只表示本次列表位置。
- 当前版本已有一次“浏览器真实模型提取→保存→网页历史”的成功样例；本地实际SDK超时经业务函数捕获并返回None已有验证；外部DeepSeek超时、实际SDK超时到HTTP502的同次联合路径、实际服务器502、完整回归及所有错误正文形式仍未全部验收。来源字段另以固定提取结果验证，不额外声称完成真实模型调用。
- 后端空技能提取列表仍会进入名称匹配并得到0，不能将其解释为用户确实没有匹配技能；模型提取内容仍需核对。
- 尚未完成全新环境安装与公开部署验证，也未实现多用户认证/数据隔离、RAG或Agent。
- 本项目为AI辅助和分步指导下的学习实践，不代表全部功能无提示独立完成。
