# AI Skill Analyzer 前端

基于 React 和 Vite 的技能匹配页面，配合 FastAPI 后端使用。用户可以手动匹配、一键从 JD 分析，或先提取技能，核对原文和修改岗位要求后再匹配。

## 当前功能

- 手动分析：输入岗位名称、本人技能和岗位要求，点击“开始分析”，结果卡显示本次提交的岗位要求、匹配/缺失技能与匹配率。后端保存该分析记录。
- 一键 JD 分析使用“从JD分析”，将岗位名称、本人技能和岗位描述发送至 `POST /analyze-jd`，展示已保存的匹配结果。结果页提供首条字面命中的原文候选、行号和可展开的本次提交原文。结果卡上方可将提取技能填入岗位要求。
- “先提取技能”使用 `POST /extract-jd`，将提取列表填入“岗位要求”，并在下方展示只读的原始提取清单及候选原文。有实际增删时，可点击“恢复提取结果”回填原清单，清空增删提示并隐藏旧分析。编辑岗位要求时，页面相对原清单显示新增和移除的技能。比较时按英文逗号拆分输入，忽略首尾空格、空项、大小写与重复项，显示时保留各自清单中首次出现的写法。修改岗位描述时会清除旧清单并隐藏增删对照。确认后用“开始分析”提交修改过的岗位要求。
- 原文定位优先展示首条包含技能名的原始行，查找时忽略大小写，空白行计入行号，显示保留原文大小写和连续空格。候选用于定位字面命中，是否属于岗位要求需要结合原文判断。
- 技能输入使用英文逗号分隔；请求前去除首尾空格并过滤空项。
- 修改输入时隐藏旧结果。三个操作按钮共用加载状态，请求期间禁用输入和按钮，结束后恢复。
- “从JD分析”检查岗位名称、本人技能和岗位描述。“先提取技能”检查岗位描述。接口错误正文中含非空字符串 detail 时显示具体提示，其他失败使用对应操作的通用提示。
- 手动加载已保存的手动/JD分析历史，显示岗位、匹配率和从1开始的展示编号，支持收起/展开。展示编号不是数据库真实ID，React列表的 `key` 仍使用真实ID；来源字段manual显示“手动输入分析”、jd显示“JD提取分析”，其他值（含旧记录null）显示“历史未标记”；新记录不会自动刷新。
- 历史请求有独立加载/失败状态，空列表有提示。

## 环境与依赖

本机检查到的工具版本：Node.js `22.19.0`、npm `10.9.3`。项目依赖声明在 `package.json`，具体安装版本由 `package-lock.json` 记录。

在 Windows PowerShell 中进入前端目录，其他存放位置请替换路径：

```powershell
cd D:\ai_analyzer_frontend
node --version
npm --version
```

首次准备新环境，或需要按锁文件重新安装依赖时执行：

```powershell
npm ci
```

`npm ci` 按锁文件安装依赖，并会替换已有的 `node_modules`。现有依赖可用时，日常启动无需重复安装。本项目尚未完成全新环境安装验证。

## 启动与前后端连接

1. 先按后端项目的 README 准备 MySQL、数据库连接和 Python 环境，再启动后端。当前本机后端目录为 `D:\ai_analyzer`。
2. 另开一个终端，在前端目录执行：

```powershell
npm run dev -- --port 5173 --strictPort
```

3. 浏览器打开 `http://localhost:5173`，保持前后端两个终端运行。需要停止对应服务时，在该终端按 `Ctrl+C`。

固定5173端口并在占用时停止启动，是为了与当前后端跨域配置一致。若提示端口占用，先确认是否已有本项目运行，不能直接停止未知进程或换端口后忽略跨域设置。

当前前端源码使用以下后端地址：

- `POST http://127.0.0.1:8000/analyze`：分析并保存。
- `POST http://127.0.0.1:8000/analyze-jd` 接收 `position`、`user_skills` 和 `jd`，提取、匹配并保存记录。
- `POST http://127.0.0.1:8000/extract-jd` 接收 `jd`，从 `data.required_skills` 返回可供确认的技能列表。
- `GET http://127.0.0.1:8000/history`：查询已保存的手动/JD分析记录。

当前后端允许的前端来源为 `http://localhost:5173`。前端页面请使用这个地址；`http://127.0.0.1:5173` 属于不同来源。后端地址仍可使用源码中的 `127.0.0.1:8000`。

## 最小运行检查

1. 填写岗位名称，本人技能输入 `python`，岗位要求输入 `python,sql`。技能之间使用英文逗号。
2. 点击“开始分析”，预期匹配技能为 `python`、缺失技能为 `sql`、匹配率为 `50.0%`。
3. 点击“加载历史”，核对刚保存的岗位、匹配率、编号及“来源：手动输入分析”。新记录暂不自动刷新到列表，需要手动加载。
4. 首次进入尚未加载时，不显示已加载条数；查询失败时应显示错误并恢复按钮。已有列表可能保留此前成功加载的数据，不代表最近一次请求成功。

### 先提取、核对与手动匹配

1. 在“岗位描述”填入 JD，点击“先提取技能”。这一步只需要岗位描述，后端使用本机配置的模型服务提取技能。
2. 对照“原始提取技能”及候选行号，直接编辑“岗位要求”。例如原清单为 `Python,MySQL`，将岗位要求改成 `python, Redis, redis` 后，原清单保持原样，页面显示新增 Redis、移除 MySQL。若提取返回空列表，页面提示手动填写岗位要求。
3. 如需撤销编辑，点击“恢复提取结果”。恢复后可继续编辑。
4. 填写岗位名称和“我的技能”，点击“开始分析”。核对结果卡中的“本次匹配的岗位要求”。历史中这条记录的来源为“手动输入分析”。

### 一键 JD 分析

1. 后端本机配置有效 `DEEPSEEK_API_KEY`，按后端README准备环境和数据库；密钥只放后端，前端不填写。
2. 填写岗位名称；“我的技能”填写英文逗号分隔的技能，在“岗位描述”粘贴JD。只有手动“岗位要求”可以留空。
3. 点击一次“从JD分析”，等待结果。通过校验后会请求外部模型，成功匹配会保存一条历史记录；不要连续点击或重复写入同一验证样例。保存失败时后端返回500，不作为保存成功展示。
4. 核对提取与匹配结果，再点击“加载历史”查看已保存的岗位、匹配率及“来源：JD提取分析”。页面匹配率表示名称规则下的技能匹配程度，不是岗位胜任度或录用概率。

检查输入提示不需要真实模型请求；页面请求失败测试应与正常分析分开。已有成功截图时，不为重复证明旧结果再次请求。后端业务提取客户端现设置 `timeout=30`、`max_retries=0`，网络操作等待超时为30秒，失败后不自动重试；它不是整个接口严格30秒的总耗时上限。参数修改仅做静态核对，尚未据此重跑正常外部模型请求。
